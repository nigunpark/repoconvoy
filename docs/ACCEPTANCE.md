# Release acceptance — RepoConvoy

The product is **not complete** until the same disposable project and exact candidate IDs pass the end-to-end path below. A component test or UI mock never replaces the owner action.

- [ ] **Project and order:** register two independent projects, select one, create a durable parent session, submit one order, and automatically select only its relevant Git repositories (not every registered repository).
- [ ] **Real workers:** start a genuine authenticated Codex coding session per selected repository in separate Git worktrees; record the native thread IDs, actual tool events, cwd, nonzero tool failures, exit state and a bounded writer lease. The worker edits files under normal sandbox permissions; the trusted controller validates and commits the candidate, because the sandbox does not grant AI tools Git metadata writes. No extra user spawn; after a restart, reconcile and resume or fail closed without duplicate writers.
- [ ] **Independent gate:** pin each candidate's base/head, run a declared product test suite with a nonzero executed count outside the model, record the command/exit/count/hash, and prevent review for a failed, skipped-only, still-writing, no-change or stale-head candidate. Board lanes match persisted evidence and do not show undispatched repositories as workers.
- [ ] **Review:** one verified card's **Review PR** opens all changed files (including added/deleted/renamed and binary limitations), exact immutable base/head blobs, file search, supported language symbols, real definition/reference navigation where a language server is available, and back navigation. Unsupported capabilities are explicitly marked unavailable.
- [ ] **Native AI conversation and edit:** the configured provider's persistent thread receives the server-derived code bytes and the chosen repo/SHA/file/side/visible lines/selection; scrolling or switching tabs cannot apply a stale response. A same-thread edit instruction changes real isolated candidate files, shows tool activity and patch, advances head, invalidates old tests/approval, re-verifies and only then unlocks a new review decision.
- [ ] **Approval and publication:** rejection or stale approval causes zero remote writes. Explicit approval of the exact revalidated head permits one GitHub branch/PR creation; independently read back host repo/base/head and PR URL/number, and avoid duplicate PRs on retry. Unsupported Git hosts fail closed. GitLab MR publishing is not claimed as live-tested without a GitLab account.
- [ ] **Installed run:** install a self-contained Windows build in an isolated profile and repeat the **same** order → worker → tests → review → edit → new tests → decision → GitHub PR readback using disposable repositories and an owner-approved private GitHub test repo. Capture logs/screenshots without user paths or credentials. Host-side CI and merge are outside RepoConvoy's completion contract.

The original Gemini-generated PNG is **not** a product asset. New vector artwork must not reuse source pixels; public reachable history should not expose the old asset after the owner-approved initial history rewrite. GitHub's caches or externally saved commit links may persist outside ordinary branch history and must not be described as verifiably erased.
